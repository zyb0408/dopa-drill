# Dopa Drill（ドパドリル）— 公开版规格说明书

Dopa Drill（ドパドリル）是一款浏览器游戏，每次解出计算题，吉祥物的动作、画面演出和音乐都会随之增强。本书面向玩家、家长以及关心开发与改造的人士，说明当前实现的运行方式。数值在今后的调整中可能会变更。

## 1. 概要与设计理念

目标是让玩家每天持续进行少量计算，并能确认自己相较过去的成长。基础题目即使超过限时也能继续作答，全部答对即可获得100分。没有游戏结束（Game Over）。

误答会显示「差一点」，可重新作答。已获得的星、成就（奖杯）、演出不会因失败或缺席而被收回。连续记录设有弥补休息日的机制，成长对比中仅显示有改善的项目。奖励在达成条件后解锁，不会通过抽选或付费获取。

界面为日文，面向小学生的计算练习和成人使用。以智能手机竖屏为主，也可通过PC的鼠标和键盘操作。无需注册账号。记录按浏览器分别保存，因此不会与其他设备自动同步。

## 2. 画面与流程

### 2.1 画面一览

| 画面 | 内容与主操作 |
| --- | --- |
| 标题画面 | 标志、Dopa Kichi（ドパキチ，吉祥物）、个人水平模式、其正下方的复习模式、1〜6年级、技能树、成就（奖杯）、收藏、任务、日历、设置、？ |
| 游戏画面 | 题目、输入位、专用数字键盘、答对数量、差一点次数、时钟、Dopa（演出数值）、连击、进度显示、静音 |

| 最终结果画面 | 含Extra（加时挑战）的得分与Dopa（演出数值）、答对数量、差一点次数、任务、重玩・返回标题画面的操作 |
| 技能树 | 前置关系、解锁・练习・精通的状态、星、生锈、技能说明与练习、记录的部分删除 |

通常按「标题画面 → 基础题目 → 基础结果画面 → 任意Extra（加时挑战） → 最终结果画面」进行。复习模式只到基础结果画面为止。结果画面的操作按钮固定在底部，即使成长记录增加也能进入下一步操作。

### 2.2 首次引导与「？」帮助

首次会显示5页的引导。顺序为：导入、个人水平模式、按年级模式、技能树、推荐个人水平模式的说明。设置按钮下方的「？」可重新显示加入成就（奖杯）和收藏后的7页说明。

用聚光灯照亮说明对象，必要时滚动。说明文字显示在独立卡片中，Dopa Kichi（ドパキチ，吉祥物）通过移动、指点和表情进行引导。不会以Dopa Kichi（ドパキチ，吉祥物）的台词形式显示。最后会指向「个人水平模式」和「？」，若同时无法容纳在画面内，则在卡片内显示同样的问号图标。

通过「下一步」「返回」「跳过」以及最后的「开始！」进行操作。Enter・右箭头为下一步，左箭头为上一步，Escape为跳过，Tab为引导内的焦点移动。点击暗色遮罩也不会关闭，引导中无法操作背景的按钮。

无论看到最后还是跳过了，都会作为已显示而保存。首次引导之后，按补签锤、登录奖励、成就（奖杯）通知的顺序处理。全部重置后会再次显示首次引导。演示模式中和部分用于确认的URL不会自动显示。

## 3. 模式

### 3.1 个人水平模式

首次为「实力检测」。按年级、前置关系深度排序推进技能，若首次答对，则将出题对象及其前置技能一并设为精通・☆1。移动幅度初始为6，答对后将当前幅度乘以1.3并向上取整、最大12，误答后将一半向下取整、最小1。误答后会退回到最后一次首次答对位置之前的范围内。完成基础题目后即标记为已检测。

之后的出题基于前置关系深度、年级、技能定义顺序进行选择。从未精通的末尾6个技能中选择复习，复习栏为 `min(候补数, max(1, round(题目数 × 0.3)))` 题。优先生锈的技能，其余从候选中随机选择。若没有已精通的技能，则复习栏为0。

其余按顺序循环已解锁・未精通的前4个技能。若全部已精通则从未精通整体中选择。Extra（加时挑战）选择未精通候选的末尾3个技能，若没有则从已精通的末尾3个技能循环。检测刚结束后的Extra（加时挑战），从已解锁・未精通的开头选择。

### 3.2 按年级模式

不论解锁状态如何，从所选年级的技能中出基础题目。在从浅到深的前置关系排列中加入随机数的波动。解答结果也会反映到通常的熟练度中。

Extra（加时挑战）的前6题循环该年级技能列 `floor(技能数 × 0.55)` 号之后的部分。从第7题起切换到下一年级开头最多4个技能。6年级则继续同一年级的后半部分。

### 3.3 练习模式

从技能树中选择已解锁的技能进行练习。若已精通，可从说明画面开始练习。基础题目为该技能，Extra（加时挑战）从该技能直接作为前置的已解锁技能中选择。若无对象则继续同一技能。

在按年级模式和练习模式中，满足条件的时光胶囊可能会替换基础题目中的1题。这1题可能会超出指定的年级・技能范围。

### 3.4 复习模式

在解答到包含误答的题目最后时，最多保存40题题目本身。以题目的标题和算式作为标识符去重。中断的未完成题目不添加。

可从标题画面和结果画面的重玩按钮开始。从已保存列表的末尾开始，以上限为所设题目数量与10中较小的一方进行选择。即使从结果按钮开始，也不限于该次的误答，而是使用之前留存下来的列表。

首次答对后重做的题目从列表中删除，再次误答的题目保留。全部答对即获得100分，没有Extra（加时挑战）。也会反映在通常的成长记录・熟练度・任务中。

### 3.5 演示模式

在设置中的「自动观看游戏」开始自动操作。从全部技能中选择的问题按由易到难排列，Extra（加时挑战）从4年级以上的技能中选择。使用通常的输入・判定・演出，也会包含误答。基础中误答题数的上限为 `floor(题目数 × 0.2)`。

基础、Extra（加时挑战）、最终结果各进行一轮后返回标题画面，解除演示。也可通过点击・按键操作结束。开始后立即点击有600ms的忽略时间。演示的游戏结果不计入历史・熟练度・复习・成长统计，也不推进任务或成就（奖杯）的获取。返回标题画面后仍进行通常的登录处理。

固定的演出在演示中也会使用，仅从已解锁的「随机」分类中选择。URL中的 `?demo` 是与该自动操作不同的功能。

## 4. 一次游戏与输入

### 4.1 基础题目与Extra（加时挑战）

题目数为6・10・14题，初始值为10题。基础的目标时间为 `ceil(题目数 × 18 ÷ 10) × 10` 秒，6题为110秒、10题为180秒、14题为260秒。超过仍可继续，不会扣分。基础的中经过时间从游戏开始到完成为止，包含题目的切换。

「答对」是完成至最终解的题目数，「差一点」是受理的数字相对于当前输入位为错误的次数。「首次答对」是包含中途输入、一次也未误答就完成的题目。基础中首次答对数除以题目数所得比例在0.8以上时，可选择Extra（加时挑战）。

Extra（加时挑战）默认90秒。在开始处理的时刻加上90,000ms与导入用的900ms来设定期限。并非从最初可输入时刻起保证90秒的方式，题目切换过程中时钟也在走。确认对话框期间停止。时间到则确定得分，进入最终结果画面。未完成题目不计分，但因已受理的答对输入位而增加的Dopa（演出数值）会保留。

### 4.2 数字输入

使用专用数字键盘和PC的数字键逐位输入，并在当场判定。没有回答确定按钮。正确的数位会被保留，错误的数字在下次输入时替换。Backspace操作用于删除当前错误的数字，不会取消已答对的位数。

在智能手机上，根据包含浏览器操作栏的显示区域调整题目的留白和数字键盘的高度。将包含0和删除的最下段配置在底部安全区域之上，屏幕尺寸变化时重新计算题目的文字大小。

| 题目形式 | 输入顺序与自动显示 |
| --- | --- |
| 横排算式 | 从答案左侧的位数开始输入 |
| 带余数的横排除法 | 商、余数的顺序 |
| 加减竖式 | 从最下方的位开始。自动显示进位・退位（借位）的辅助数字 |
| 乘法竖式 | 从右侧输入部分积，存在多个部分积时将合计也从右侧输入 |
| 除法竖式 | 商的上一位、减去的剩余、下一个商的顺序。积・移下的数字・最后的余数0自动显示 |
| 小数 | 自动显示小数点，只输入数字 |
| 分数 | 分母、分子的顺序。带分数为整数部分、分母、分子的顺序 |
| 比・字母式・近似数・百分比 | 从指定空格的左侧位数开始输入 |

分数按准备的回答形式判定。3年级的同分母分数保留原分母，接受未约分的答案。其他分数计算使用生成的既约分数・带分数形式。并非自由输入等价其他表达来判定的方式。

### 4.3 误答与提示

错误的数字使用紫色点线边框。在相同输入位误答2次时，若定义了应参照的数字则进行强调・指点。第3次起显示计算的途中式或乘法口诀列等提示。提示中可能包含相当于答案的值。

误答会使连击变为0，但不减少得分・Dopa（演出数值），并维持演出阶段和背景音乐。因误答音会暂时压低背景音乐，使用弹跳的音效和Dopa Kichi（ドパキチ，吉祥物）恢复的表演。

## 5. 得分・Dopa（演出数值）・连击

### 5.1 得分

基础完成为100分。将Extra（加时挑战）已完成题目以0起始记为 `k` 时，该题的加分为 `10 + 5 × k` 分。完成 `n` 题Extra（加时挑战）的合计得分如下式。

```text
100 + 10 × n + 5 × n × (n − 1) ÷ 2
```

5题200分、10题425分、15题775分、23题1595分、30题2575分。得分没有固定上限。连击・解答速度・差一点次数不会带来得分倍率或扣分。

### 5.2 Dopa（演出数值）的计算

Dopa（演出数值）是演出的数值，与得分不同。内部值 `L` 取常用对数，显示值的原值为 `10^L`。游戏开始时 `L = 0`。

基础基准曲线为 `B(f) = 2.3 × clamp(f, 0, 1)^1.15`，Extra（加时挑战）基准曲线为 `X(n) = 2.3 + 3.0 × (1 − exp(−n / 10))`。

将基础总题目数记为 `N`、已完成题目数以0起始记为 `q`、当前题目的回答输入位数记为 `m`、本次答对的输入位以1起始记为 `s` 时，该输入的基准增量为 `B((q + s/m)/N) − B((q + (s−1)/m)/N)`。将Extra（加时挑战）已完成题目数记为 `k` 时，1个输入位的基准增量为 `(X(k+1) − X(k))/m`。

答对时先使连击数 `c` 加1，按下式反映该输入。

```text
倍率 M(c) = 1 + (2 − 1) × min(1, max(0, c) / 20)
新 L = min(9.08, L + max(0.003, 基准增量) × M(c))
```

10连击为1.5倍、20连击以上为2倍。上限是对数值9.08，原显示值准确为 `10^9.08`。由于增量有最低值0.003，实际到达值并非仅由基准曲线终点决定。首次答对也为1连击・1.05倍，Extra（加时挑战）开始时将连击归零并继承Dopa（演出数值）。

显示将1万以下四舍五入为整数，之后附加「万」「億」等。单位内的值小于10时显示到小数点后第1位，10以上则显示舍去小数后的整数。到达100、1000、1万、10万、100万、1000万、1亿时有里程碑式的演出。通常游戏的上限不会到达兆以上。

### 5.3 连击的时间与显示

每个正确的回答输入位加1连击，并跨题目保留。2连击以上开始显示，20连击以上显示「Dopa（演出数值）×2 MAX」。误答或时间到归零。不过，在当前实现中1连击状态不在时间到判定对象内。

年级 `g` 的通常输入位时间为 `3000 + 600 × (g − 1)` ms，题目的第一个输入位加2500ms。年级限定在1〜6，不明确时按3处理。

| 年级 | 通常输入位 | 题目的第一个输入位 |
| --- | --- | --- |
| 1 | 3000ms | 5500ms |
| 2 | 3600ms | 6100ms |
| 3 | 4200ms | 6700ms |
| 4 | 4800ms | 7300ms |
| 5 | 5400ms | 7900ms |
| 6 | 6000ms | 8500ms |

在接收输入的时点设定期限，题目切换和确认对话框不消耗时间。剩余时间条在30%以下时强调。10・20・30・50・75连击、100以上每50连击大幅庆祝。5连击以上中断时简短显示结束的连击数。

## 6. 出题范围与技能树

### 6.1 范围与生成

计算分为58个技能。按年级模式中1年级8个、2年级13个、3年级14个、4年级10个、5年级8个、6年级5个。系统（系統）有「加・减」「乘・除」「小数・分数」「其他」4类。全部技能的名称・标识符・前置・生成条件汇总于 `docs/curriculum.md`。

对象为四则计算、伴随中途输入的竖式、小数、分数、近似数、约数・倍数、计算顺序、百分比、相等的比例、未知数（字母的值）。图形、测量、图表、应用题、汉字数字输入不出题。

每次根据技能条件用随机数生成。使用最近24题的签名和该次游戏内已出过的签名来避免重复。候选生成有重试上限，因此在候选较少的技能等处可能出现重复。时光胶囊和复习是为例外，用于重现同一题目。

### 6.2 显示与解锁

以每系统分2列共8列显示，窄画面中可纵向横向滚动。优先按年级顺序排列，5・6年级置于1〜4年级之下。前置关系的连线绕开其他节点，仅排在同一列并不意味着依赖关系。

无前置的技能从最初即解锁，多个前置则需全部精通。状态区分锁定、NEW（新解锁）、练习中、精通。通常的精通条件是：至少有6题历史，且最近6题中5题以上为首次答对。一旦精通的技能即使误答也不会回退。实力检测的一并授予是该次数条件的例外。

### 6.3 技能的星

精通后依次获得☆1〜☆5。需逐级满足条件，若满足则同一判定可上升多个阶段。合计最大为290。

速度的判定使用每题的回答时间除以基准时间所得的比率。基准时间为 `第一个输入位的连击时间 + max(0, 回答输入位数 − 1) × 通常输入位的连击时间`。仅从对象的首次答对题目中求出比率的中位数。

| 星 | 条件 |
| --- | --- |
| ☆1 | 已精通 |
| ☆2 | 最近20题齐全，首次答对率0.9以上 |
| ☆3 | 最近10题齐全，其中5题以上为首次答对，时间比率中位数在1以下 |
| ☆4 | 最近3题全部首次答对，且各题日期在☆3获得日7天之后 |
| ☆5 | 最近20题齐全，首次答对率0.95以上，时间比率中位数在0.6以下 |

☆4的3题不限于同一天。星在通常游戏或休息时不减少，在技能记录删除和全部重置时消失。说明画面显示下一颗星的条件、当前值、解答的题目数、最短的答题时间。

### 6.4 生锈

将已精通且最后一次首次答对起经过 `21 × 86400000` ms以上的技能作为候选，按从旧到新的顺序对最多3个显示「生锈」。若无首次答对日期时间，则按实力检测的授予日期时间、精通日期时间的顺序参照。

生锈的技能答对1题首次答对即被打磨，在保持星的同时标记消失。因打磨，其他较旧的技能可能成为显示对象。用于个人水平模式的复习和打磨任务。

### 6.5 技能的记录删除

长按有记录的技能600ms，或聚焦后按Delete则打开确认。从按下位置移动超过10px则中止长按操作。

确定后，删除该技能以及直接・间接依赖它的技能的记录・星。所选技能若前置仍在则为NEW（新解锁），前置不齐则回到锁定。历史、复习、累计统计、成就（奖杯）、收藏、实力检测完成状态予以保留。

## 7. 持续的机制

### 7.1 历史・日历・登录奖励

在基础结果画面保存历史，Extra（加时挑战）结束后更新同一历史的得分・追加答对数量・差一点・Dopa（演出数值）。最多保留3000件。日历显示各日的最高得分和游戏次数，可从日期打开详情。可移动到过去的月份，不前进到未来的月份。

连续天数以今天为起点，若今天尚未游玩则以昨天为起点计数。也显示最长记录和登录贴纸的数量。游玩日和登录日分开，仅打开标题画面不算游玩日。

登录奖励按设备日期每天1次。按星、心、花、音符、四叶草、优圈、皇冠的7天周期领取贴纸。若夹有未设为不计的缺席日则周期从最初重新计数。贴纸在打开显示的时点为已获取，即使关闭或重新加载也不会在同一天重复领取。

### 7.2 补签锤

用1把将未游玩的1天设为不计，连接游玩・登录的连续记录。不会将该天加入游玩天数，也不会追加休息日的贴纸。初始持有1把，持有上限3把。

最后游玩日在最近7天以内、且可用持有数量填满截至昨天的空日、并能保持2天以上连续时，在标题画面每天建议1次使用。拒绝的当天不再建议。使用后向日历盖上不计的印章。使用历史最多50件。

### 7.3 每日任务

根据设备日期和当天选择时的记录，决定并保存2个简单的和1个费时的任务。同一天即使更改设置也不会重新选择。日期变更后的更新处理切换为新列表。候选有固定11种和应对生锈的1种。

| 栏 | 候选与达成条件 |
| --- | --- |
| 简单 | 1次完成、5连击、首次答对5题、复习1题、NEW（新解锁）技能1题 |
| 费时的 | 进入Extra（加时挑战）、Extra（加时挑战）5题、20连击、2次完成、按年级模式1次完成、NEW（新解锁）或练习中的技能10题、指定技能的首次答对3题 |

无复习・NEW（新解锁）对象时除去相应候选。Extra（加时挑战）相关需在最近5份历史中有Extra（加时挑战）记录，20连击需 `题目数 × 平均回答输入位数 >= 26`，练习中10题需已完成实力检测且有未精通候选。不将同一指标的任务叠加于同一天。

所需时间的选择模型将1次设为 `(题目数 × 18 + 计入Extra（加时挑战）时90 + 30) / 60` 分。首次答对5题预计 `ceil(5 / (题目数 × 0.7))` 次，练习中10题预计 `ceil(10 / (题目数 × 0.6))` 次，20连击预计2次。复习按最多10题计算，叠加各模式间可共同达成的项目，选择合计15分以内的组合。这仅为估算，并非限制实际所需时间。

打磨候选为：在生锈的日子里日期来源的随机数小于0.5，且最近7天提示次数小于2时成为选择对象。可从标题画面开始目标技能的练习，达成需同一技能3题首次答对。这与生锈本身消失所需的1题条件不同。

进度在游戏中累加，达成时从画面上端通知。复习也累加到共同的完成・首次答对・连击条件。3个全部达成时当天仅1次领取1把锤子，并在日历上做标记。若已达持有上限则仅显示演出，奖励不顺延至日后。

### 7.5 与上次比较

在基础结果画面，将同一技能相比以前记录提升之处以「进步了！」最多显示3行。本次与比较对象双方都需有3题以上。比较对象为：上次游玩日、21天以前的最近日、最初解答的3题。不会仅将同日内的过去轮次作为比较对象。

解答时间按每回答输入位的平均比较，显示为换算为本次平均输入位数的每题秒数。候选为时间缩短10%以上、或首次答对率改善10个百分点以上的项目。各技能选1个最大改善，整体按改善大小顺序显示。无改善则不显示。实力检测・演示・停止成长记录的确认用URL不在对象内。

### 7.6 时光胶囊

从各技能保存的最初3题中，选择已精通、且从解答时起经过 `30 × 86400000` ms以上未使用问题中最早的一个。

通常的个人水平模式、按年级模式、练习模式的基本集合在4题以上时，替换以0起始的 `max(1, min(N−2, floor(N/2)))` 号。实力检测、复习、Extra（加时挑战）、演示、停止成长记录的确认用URL不在对象内。每天最多1题，因保存预告结束时的日期，之后即使中断也不在同一天再次提示。在题目完成时变为已使用。

通过信封预告和橙色边框，让人知道这是过去的题目。比较时若本次时间小于过去的0.95倍则为时间缩短，否则为误答次数减少，若两者皆无则显示再次解出及日期。恰好缩短5%时不显示为时间缩短。

## 8. Dopa Kichi（ドパキチ，吉祥物）与演出・音

Dopa Kichi（ドパキチ，吉祥物）原则上是非语言的。造型基准为 `docs/dopakichi.svg`。具有横向的大耳朵、横向宽圆的头、奶油色的脸和肚子、双重圆圈的眼睛、细的手臂和蓝色的脚。基本色为粉 `#FF97BF`、奶油 `#FFF3E4`、耳朵内侧 `#FFE6F0`、蓝 `#2F79F7`、轮廓 `#000000`。

输入的数字用空着的手搬运。左右手可分别搬运不同数字，判定与搬运分离，不等待下一次输入。途中答对・最终答对使用跳跃、拍手、旋转等，误答时崩溃后恢复。误答表演有10种，序盘4种、中盘8种、强度0.6以上从10种中，避开与刚才相同的选择。

将基础题目编号以0起始记为 `i`、题目数记为 `N` 时，演出强度为 `E = 0.08 + 0.92 × (i/(N−1))^1.3`。仅1题时设为 `E = 1`。Extra（加时挑战）对已完成数 `k` 有 `tier = floor(k/3)`、`E = 1 + min(0.5, tier × 0.1)`。

根据强度叠加背景、优圈等答对标记、纸屑・星・烟花・硬币、观众、行军、临门一脚、灯饰、晃动。终场表演从巨型Dopa Kichi（ドパキチ，吉祥物）、烟花大会、火箭、游行中选择，最后显示100分。保持输入与数字键盘的布局、竖式位数对应。

音乐与音效用Web Audio API合成，不加载外部录音素材。基础为马林巴进行曲，另加8位、祭典伴奏、管乐队、电子乐共5曲。使用振荡器・噪声・滤波器和混响等，逐步叠加打击乐、低音、和音、旋律。

基础的速度为 `112 + min(1, E) × 16` BPM，通常最初为113.28 BPM、最后为128 BPM。最终题从基准升高2个半音。Extra（加时挑战）为 `134 + tier × 5` BPM，调为从基准起 `2 + min(tier, 5)` 个半音。转调有上限，速度没有该式的固定上限。

用声音补充按键、数字落地、答对、误答、Dopa（演出数值）的里程碑、时钟等，音高与曲的和音同步。声音的开始使用浏览器要求的用户操作。背景使用WebGL，不可用或上下文丢失时切换到CSS背景。

全部重置第1次显示通过「全部重置」将删除的内容，第2次通过「真的要删除吗？」确认无法恢复。两者均以「取消」为初始焦点。取消、Escape、背景点击不删除。第2次确定时，删除所有带 `dopa-drill` 前缀的保存键，丢弃内存缓存并重新加载。无关键保留。

## 10. 保存与隐私

保存位置为浏览器的localStorage，键为 `dopa-drill:v1`、数据版本为1。没有输入姓名等个人信息的栏位，应用不向服务器发送学习记录。没有广告、外部分析、排行榜、设备间同步。从分发服务器获取游戏的静态文件运行。

在保存区域不可用、读取失败、JSON损坏的情况下，以初始状态启动，即使保存失败也继续当场游戏。浏览器数据清除、保存限制、在别的浏览器或分发源使用时，无法继承记录。

## 11. 技术构成・运行・验证

### 11.2 启动与测试

从仓库根目录，例如用以下命令即可静态分发。在显示的服务器地址打开 `/app/`。因使用ES Modules，不通过HTTP直接打开HTML文件，而是通过HTTP分发。

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

使用Node.js的测试用以下命令运行。

```sh
node --test tests/*.test.mjs
```

产品的测试为 `tests/app_*.test.mjs` 的11文件・58件。上述命令也包含附带的其他测试，因此整体件数因分发物而异。在仅显示文件单位件数的Node.js环境中，在相应环境加 `--experimental-test-isolation=none` 即可汇总个别测试。

检查题目生成・输入步骤、得分、保存与重置、技能・星、出题计划、成长比较、任务、成就（奖杯）、解锁演出、引导的布置计算。自动测试的成功不替代实机的绘制・音质・操作感验证。

### 11.3 用于确认的URL参数

按 `/app/?count=6&seed=123` 的方式指定。

| 参数 | 动作 |
| --- | --- |
| `count=6`、`count=10`、`count=14` | 选择启动时的题目数 |
| `seed=<数值>` | 固定用于题目选择・生成等的随机数。不固定全部视觉效果的随机数 |
| `extra=<秒>` | 替换Extra（加时挑战）的默认90秒。开始时加900ms为共用 |
| `skill=<技能ID>` | 将通常的题目选择替换为该技能。与复习或固定模板并用时存在选择处理的优先顺序 |
| `demo` | 从个人水平模式入口开始固定模板的基础集合。首题为27＋35。不进行自动操作 |
| `capture` | 收集声音事件的确认路径。抑制通常的实时声音输出与自动引导・标题奖励通知等 |

在 `skill` 与固定模板的游戏中，停止通常的答题时间・成长统计・任务，但完成历史和复习会保存。在 `skill` 中，若出题计划为实力检测，则该计划侧的精通授予与检测完成保存也会运行。成就（奖杯）判定在 `skill` 与 `capture` 中停止，但仅指定 `demo` 不停止。`capture` 也会继续通常的进度・历史・统计的保存。请勿将这些作为不留记录的练习功能使用。
